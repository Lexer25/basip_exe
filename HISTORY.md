   на диск сразу, поэтому при аварийной остановке службы последние записи не теряются
   (Serilog держит их в буфере).

Версия: 2.0.4.0
1. Адрес журнала событий выбирается по мажорной версии API панели: для 1.x — GET /api/v1/log/list
   с фильтром filter=timestamp+ge+<метка времени в мс>, для 2.x и выше — GET /api/v1/log/items
   с параметром from. Раньше всегда запрашивался log/items, и панели 1.x (прошивка 3.13.x)
   отдавали системный журнал (вход в веб-интерфейс) вместо журнала проходов.
2. Каждая строка журнала помечается панелью сразу после уровня: "[DBG][617] текст" — запись об
   обработке панели, "[DBG][sys] текст" — запись не связана с панелью (запуск, итерация, таймаут,
   ошибки запуска, служебные сообщения хоста). Тексты сообщений при этом не изменялись.
3. Параметр Log:LogLevel теперь задаёт уровень журнала для категорий приложения (Basip.*):
   Worker, DB, Device, Basip.DebugOutput, StartupFailureService. Раньше он применялся только
   к файловому приёмнику, а общий фильтр отсекал Debug и Trace, поэтому отладочные записи
   (в том числе дампы запросов и ответов) в файл не попадали.
4. При каждом запуске в журнал пишется версия программы и путь к исполняемому файлу; в строку
   "126 timeout basip" добавлено время следующего запуска; результат запроса журнала пишется
   строкой "455 GetLog result: status=..., body=...".
5. Незаполненная конфигурация больше не приводит к падению с необработанным исключением: причина
   пишется в журнал (в том числе в файл), служба завершается с кодом возврата 1. Если каталог
   журнала недоступен на запись, журнал ведётся в первом доступном каталоге.
6. Версии приведены к 2.0.4.0: приложение (Basip.csproj), установщик (BasipSetup.iss), build.bat.
   README обновлён под текущее поведение (формат строки журнала, уровни, адрес журнала, отладка
   на одной панели).
7. За одну итерацию забираются ВСЕ страницы журнала, накопившиеся с метки LASTEVENT, а не только
   одна: раньше за прогон обрабатывалось не более limit (50) событий, поэтому накопление в 1000
   событий требовало 20 запусков. Страховка — не более 200 страниц (10 000 событий) за итерацию,
   остаток забирается следующей (пишется предупреждение).
8. Номер идентификатора (карты) в событии разбирается для обоих вариантов API: у 1.x он лежит
   прямо в info (info.number), у 2.x — в info.model (info.model.number). Раньше читался только
   info.model, поэтому на панелях с API 1.x карта в событии не определялась и в событие СКУД
   уходил пустой note. Разбор вынесен в LogItem.IdentifierNumber: ключи number, card, code, owner,
   значение принимается и строкой, и числом. В LogInfo добавлен приём неизвестных полей
   ([JsonExtensionData]), поэтому поля API 1.x (type, apartment_address, localized и т. д.)
   доступны как info.fields.

    панель на запрос журнала событий. Учтите, что GetEvents вызывает GetLog дважды за цикл
    (пробная страница и последняя), поэтому результат пишется дважды на панель.
18. Адрес и параметры запроса журнала зависят от мажорной версии API панели
    (Device.major_api_version, выставляет Worker из api_version): для 1.x — "log/list"
    с фильтром "filter=timestamp+ge+<мс>", для 2.x и выше — "log/items" с параметром from.
    Из запроса убран sort_type. Панели с прошивкой 3.13.x (api 1.3.5) на "log/items"
    возвращали системный журнал (successful_login_api_call) вместо журнала проходов.

    Log:LogLevel для категорий Basip.*, адрес журнала по версии API (log/list для 1.x,
    log/items для 2.x), имя файла журнала с датой, поведение при ошибках запуска,
    раздел про отладку на одной панели.
20. Device.GetEvents собирает события со всех страниц журнала, накопившихся с метки LASTEVENT:
    первая страница (пробный запрос) даёт total_items, далее запрашиваются страницы 2..N,
    их list_items объединяются в один ответ для Worker. Раньше возвращалась только последняя
    страница, поэтому за итерацию обрабатывалось не более limit (50) событий, и накопление
    в 1000 событий требовало 20 запусков. Ограничение — MaxEventPagesPerRun = 200 страниц
    за итерацию (остаток забирается следующей, пишется предупреждение). Ход виден по строкам
    334 (всего событий и страниц), 367 (страница получена) и 370 (собрано событий).
